# AGENT_RULES.md — Antigravity Agent 強制開發與協作規範

本文件為 AI Agent（Antigravity Agent）開發本專案的最高行動指南。在任何開發、除錯、重構或文件維護工作中，必須嚴格遵守以下條款：

---

## 1. 極致省 Token 原則（架構邊界隔離）
- **按區塊載入**：每次執行任務時，**僅能讀取與當前進行中之「架構區塊」直接相關的程式碼與檔案**。
- **跨區塊通訊一律以契約為準**：不同區塊間的互動規範全部定義於 `docs/CONTRACT.md`。寫 iOS 程式碼時絕不載入 Python 腳本，寫後端時不載入 SwiftUI 代碼。
- **單一事實來源（SSOT）**：嚴禁在多份文件中重複抄寫相同的設定步驟或長篇清單，彼此透過 Markdown 連結交互參照。

---

## 2. 任務開始前之標準檢查工作流
每次開始處理新任務前，必須依照下列順序執行檢查：
1. **讀取進度**：讀取 `docs/PROGRESS.md`，掌握目前各區塊的完成百分比與最新開發日誌。
2. **掃描靈感與待討論項目**：讀取 `docs/IDEAS.md` 中帶有當前區塊標籤（如 `[區塊 1]`）的所有待辦項目。若有相關提案，**必須主動向使用者提出討論**，確認是否納入本次任務實作。
3. **查閱錯誤庫**：若當前任務涉及過去曾踩坑的模組，先檢視 `docs/ISSUES_AND_QA.md` 避免重複犯錯。

---

## 3. 微步迭代與「嚴禁盲目寫碼」規範
- **切勿一次性寫入大量未測試代碼**：專案採微步推進，每次只實作一個明確的小功能點（例如「建立持久化登入腳本」）。
- **每次變更後必同步兩大文件**：
  - 更新 `docs/PROGRESS.md`：記錄當日（`YYYY-MM-DD`）完成項目、改動檔案，並精確調整該區塊的完成度百分比。
  - 更新 `docs/TESTING.md`：即時補上可被使用者驗證的測試步驟（前置條件、操作步驟、預期結果、驗收狀態）。
- **主動停步請求驗證**：完成上述工作後，必須暫停動作，清楚說明驗證方式並請使用者實際執行測試，待使用者確認通過後才能推進下一個子任務。

---

## 4. 錯誤排查與問答歸檔原則
- **錯誤紀錄（第一部分）**：
  - 當遇到任何執行報錯、環境異常或 IG 網頁結構改變時，除錯前先檢索 `docs/ISSUES_AND_QA.md`。
  - 問題解決後，**必須立即將錯誤現象、根本原因（RCA）、解決方案收錄至 `docs/ISSUES_AND_QA.md` 的第一部分**。
- **問答與架構決策歸檔（第二部分）**：
  - 每當使用者針對本專案的技術選型、架構設計、流程或環境配置提出問題並得到解答後，**回答完畢後必須將「日期、問題、結論與原因」摘要記錄於 `docs/ISSUES_AND_QA.md` 的第二部分（QA 清單）**。
