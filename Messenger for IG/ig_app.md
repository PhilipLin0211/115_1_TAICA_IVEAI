# 專案企劃書：PureIG Chat（純淨版 IG 私訊 iOS 客戶端）

## 1. 專案願景與核心架構

### 1.1 專案目標
打造一個專屬於個人的 iOS 原生聊天應用程式，徹底隔離 Instagram 的演算法推薦（首頁動態、探索頁面、Reels 短影音），僅保留「即時私訊收發」與「推播通知」核心功能。

### 1.2 系統架構拆分（以架構區塊作為開發單位）
**架構確認**：本專案以**「架構區塊（Architectural Modules）」**作為開發與進度計算單位。
在「瀏覽器中間人（Browser-in-the-Middle）」架構下，各層職責高度獨立。以架構區塊拆分能讓 AI Agent 在開發某個區塊時，**只需讀取該區塊的資料夾與通訊契約，完全不必載入其他區塊的程式碼**，這是節省 Token 最核心的策略。

本專案劃分為以下四大區塊：
* **區塊 0：通訊契約與管理文件層（`docs/`）** — 定義各區塊之間的資料格式與專案記憶庫。
* **區塊 1：電腦端瀏覽器 Agent（`agent-browser/`）** — 透過 Playwright 常駐掛載 IG 網頁版，負責攔截新訊息與模擬真人輸入發送。
* **區塊 2：中繼後端與推播服務（`backend-relay/`）** — 負責訊息暫存、WebSocket 即時轉發，以及串接 Apple APNs 發送手機背景通知。
* **區塊 3：iOS 原生前端 App（`ios-app/`）** — 使用 SwiftUI 開發的純淨聊天介面，僅與中繼後端通訊。

## 2. 文件管理與「極致省 Token」協作規範

透過以下六份結構化文件，建立專案的「外部長期記憶」，讓 Antigravity Agent 每次啟動都能用最少 Token 精準接續開發，且不會重複犯錯或重新猜測介面格式：

1. **`README.md`（專案總覽與地圖）**
   * 說明專案目標、環境需求、啟動指令與資料夾地圖，讓 Agent 每次開啟專案能用最少字數掌握全貌。
2. **`docs/CONTRACT.md`（跨區塊通訊契約 — 省 Token 核心）**
   * 嚴格定義 `agent-browser` ↔ `backend-relay` ↔ `ios-app` 之間的 REST API 與 WebSocket JSON 結構。寫 Swift 時不用讀 Python 程式碼，只要看這份契約即可。
3. **`docs/PROGRESS.md`（每日進度與區塊完成度追蹤）**
   * **更新時機**：只要有任何檔案更動或小功能完成，**必須立刻更新**此檔案。
   * **追蹤維度**：包含「各架構區塊完成度總覽（百分比進度條）」以及「以天為單位（YYYY-MM-DD）的開發日誌」。
4. **`docs/TESTING.md`（階段性驗收與測試手冊）**
   * **更新時機**：每完成一個微小的實作進度，立即補上對應的「手動/自動驗證步驟」與「預期結果」，確保每一步都符合預期才往下推進。
5. **`docs/IDEAS.md`（靈感與待討論想法暫存區）**
   * **紀錄方式**：開發過程中冒出但「不適合當前進度實作」的想法，先記錄於此並標註 `[區塊標籤]`。
   * **自動提醒機制**：每當準備開發某個區塊前，Agent 必須先掃描對應標籤的項目，主動提出討論是否納入本次實作。
6. **`docs/ISSUES_AND_QA.md`（錯誤排除與專案問答紀錄 — 避免重複踩坑）**
   * **錯誤紀錄**：專案開發或執行過程中出現的任何 Bug、環境報錯或 IG 網頁版變動，連同「錯誤原因」與「解決方案」記錄於此，防止 Agent 日後重蹈覆轍浪費 Token 除錯。
   * **問答紀錄**：完整收錄開發者針對本專案提出的所有問題與最終拍板的結論，作為專案的知識庫（FAQ）。

## 4. 各架構區塊拆解與進度權重規劃

為了讓 `PROGRESS.md` 能精準計算每個區塊的完成百分比，以下將各區塊拆解為具備明確權重（總計 100%）的微任務：

### 區塊 0：基礎建設與通訊契約（`docs/`）
* `[25%]` 建立資料夾結構與六大核心管理文件
* `[50%]` 定義「收訊息 / 發訊息 / 已讀狀態」的標準 JSON 格式（`CONTRACT.md`）
* `[25%]` 制定錯誤碼與斷線重連規範

### 區塊 1：電腦端瀏覽器 Agent（`agent-browser/`）
* `[20%]` 建立 Playwright 持久化設定檔（`user_data_dir`）腳本，支援手動登入並保存 E2EE PIN 碼狀態
* `[35%]` 實作網路層封包攔截（監聽 IG 網頁版新私訊 GraphQL/WS 封包並解析為標準 JSON）
* `[30%]` 實作擬真輸入發送器（定位 `div[role="textbox"]`，加入隨機打字延遲送出訊息）
* `[15%]` 串接中繼後端（收到新訊息時 POST 給後端；透過 WebSocket 接收後端傳來的發送指令）

### 區塊 2：中繼後端與推播服務（`backend-relay/`）
* `[25%]` 建置輕量後端框架與本地資料庫（儲存聯絡人列表與近期對話紀錄）
* `[35%]` 建立雙向 WebSocket 通道（同時管理電腦端 Agent 與 iOS App 的連線路由）
* `[20%]` 實作離線訊息佇列（當手機斷線時暫存訊息，重連後自動補發）
* `[20%]` 整合 APNs（Apple Push Notification service）推播模組

### 區塊 3：iOS 原生前端 App（`ios-app/`）
* `[25%]` 建立 SwiftUI 基礎專案與純淨雙頁面 UI（對話列表頁 + 單一聊天室頁面）
* `[35%]` 實作 WebSocket 連線管理員與本地狀態同步（對應 `CONTRACT.md` 格式）
* `[20%]` 實作訊息發送框、樂觀更新（Optimistic UI）與連線狀態指示燈
* `[20%]` 註冊系統推播權限並處理點擊通知跳轉至指定聊天室

## 6. 給 Antigravity Agent 的啟動指令（閱讀本檔後請直接執行）

當你（Antigravity Agent）被要求讀取本企劃書以開始專案時，請嚴格依照以下步驟執行：

1. **建立專案骨架**：根據第 3 節的資料夾結構，建立所有資料夾與初始文件（`README.md`、`AGENT_RULES.md`、`docs/CONTRACT.md`、`docs/PROGRESS.md`、`docs/TESTING.md`、`docs/IDEAS.md`、`docs/ISSUES_AND_QA.md`）。
2. **寫入 Agent 強制工作流（`AGENT_RULES.md`）**：將以下規則寫入 `AGENT_RULES.md`，並在後續每次對話中嚴格遵守：
   * **省 Token 原則**：每次任務只讀取與當前「區塊」相關的檔案，跨區塊溝通一律只看 `docs/CONTRACT.md`。
   * **開始任務前**：先讀取 `docs/PROGRESS.md` 確認目前進度，並掃描 `docs/IDEAS.md` 是否有符合當前區塊的待討論想法，若有則先向使用者提出確認。
   * **完成微任務後**：每次只要修改程式碼，**必須同步更新 `docs/PROGRESS.md`（當日紀錄與區塊百分比）以及 `docs/TESTING.md`（該小功能的驗證步驟）**，然後停下來請使用者進行實際測試確認，切勿一次盲目寫完大量未經測試的程式碼。
   * **遇到錯誤或被提問時**：
     * 發生任何 Bug 或測試失敗時，除錯前先檢查 `docs/ISSUES_AND_QA.md` 是否已有解法；解決後**必須將原因與解法寫入 `docs/ISSUES_AND_QA.md`**。
     * 每當使用者針對本專案提出任何技術、架構或流程問題，回答完畢後**必須將「問題與最終結論」摘要寫入 `docs/ISSUES_AND_QA.md` 的第二部分**。
3. **回報就緒**：完成上述初始化後，將「區塊 0」進度更新為 `25%`，並詢問使用者是否準備好開始執行「區塊 0 的 `CONTRACT.md` 設計」或直接進入「區塊 1 的第一個微任務」。
