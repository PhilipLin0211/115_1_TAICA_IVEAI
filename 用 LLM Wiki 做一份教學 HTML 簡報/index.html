AI Agents 是什麼？
從「只會聊天的顧問」到「能動手辦事的數位特助」

你一定用過 ChatGPT 寫文章或問問題，但你有沒有想過：如何讓 AI 自己上網查即時資料、按計算機驗證數字、修改檔案，一路做到任務完成為止？這就是 AI Agent（自主型代理人）！

💡 本課核心公式：AI Agent = LLM（大腦） + Planning（規劃） + Memory（記憶） + Tool Use（工具）

01. 核心定義與演進

傳統 Chatbot vs. AI Agent：差別在哪裡？

傳統聊天機器人就像「被關在沒有網路與計算機房間裡的百科全書」——只能靠記憶回答；而 AI Agent 則走出了房間，擁有工具箱與行動迴圈。

💬 傳統 Chatbot（被動問答）

  • 單輪互動：你問一句，它憑預訓練記憶答一句。
  • 能力受限：不知道今天天氣、複雜算數易出錯。
  • 只說不做：只能給你文字建議，無法直接幫你操作軟體。

🤖 AI Agent（自主閉環執行）

  • 目標導向：給定一個大目標，自己拆解步驟並推進。
  • 連結真實世界：主動搜尋網路、查資料庫、跑程式碼。
  • 自我修正：發現工具回傳錯誤時，會調整策略重試。

02. 任務規劃 Planning

器官一：大腦如何拆解複雜任務？

人類面對「籌備一場研討會」不會想一口氣做完，而是拆成「訂場地、邀講者、發報名表」。AI Agent 也是透過兩大規劃技巧解決難題：

🪜 子目標拆解（Subgoal Decomposition）

利用 Chain-of-Thought（思維鏈） 或 Tree-of-Thoughts（思維樹），把一個龐大模糊的指令，切分成一連串具體可執行的小步驟。

🪞 自我反思（Self-Reflection）

參考 Reflexion 機制：當某個步驟執行失敗或結果不合理時，Agent 會把錯誤經驗寫進記憶，修正下一步策略，而不是盲目重複同樣的錯誤。

Wiki 條目：wiki/concepts/02-planning-and-react.md 引用：[[src-01]]
02. ReAct 推理與行動迴圈

經典範式：ReAct 怎麼讓 AI「邊想邊做」？

2022 年發表的 ReAct（Reasoning + Acting） 發現：只會思考容易胡說八道（幻覺），只會行動容易迷失方向。把兩者交錯結合，就能形成嚴謹的解題迴圈：

[Thought] 使用者問「台北今天適合穿短袖嗎？」我不知道今天的即時氣溫，必須先查詢台北天氣預報。
🔍 為什麼這很重要？ 每個決策都有白紙黑字的 Thought 軌跡，人類工程師能一眼看懂 AI 為什麼呼叫這個工具，大幅提升可信度！

03. 記憶架構 Memory

器官二：如何治好 AI 的「金魚腦」？

大型語言模型每次對話都有「記憶容量上限（Context Window）」，聊太長就會忘記開頭。AI Agent 模仿人類大腦，建立雙層記憶系統：

🗒️ 短期記憶（Short-term Memory）

就是模型當下的 Context Window（上下文視窗），用來暫存「這輪任務剛查到的資料」與「最近幾句對話」，就像桌上的便利貼，拿取最快但空間有限。

🗄️ 長期記憶（Long-term Memory）

把過去幾週的筆記與經驗轉成特徵向量，存進外部 向量資料庫（Vector DB）。需要時再用語意檢索（RAG）精準撈出來，容量幾乎無限！

🏘️ 史丹佛《Generative Agents》啟發：研究人員在虛擬小鎮讓 25 位 AI 居民生活，發現除了靠語意檢索記憶，還要評估「新近度」與「重要性」，並定期做「反思摘要」，才能維持長期人格！

04. 工具使用 Tool Use

器官三：裝上手腳，讓 AI 呼叫外部工具

既然語言模型本質上不擅長心算、也不知道即時股價，最聰明的做法就是「把專業的事交給專業工具」：

  • Function Calling（函數呼叫）：模型不直接瞎猜答案，而是輸出一串標準指令（例如 calculator("3847 * 912")），交由外部程式執行後把精確數字傳回給模型。
  • Toolformer 自我學習：Meta 論文證明，AI 可以透過自我監督學習，自己測試「在文章哪裡插入計算機或搜尋 API 能讓預測更準」，無師自通學會用工具！
  • ACI（代理人電腦介面）設計：工具說明書與參數命名必須像設計給人類的 UI 一樣直覺防呆，否則模型很容易傳錯參數格式。

05. 工程實務選型（Anthropic 指南）

關鍵觀念：Workflows vs. Autonomous Agents

Anthropic 工程團隊在《Building Effective Agents》中提醒開發者：不要為了做 Agent 而硬做 Agent！ 系統設計其實分成兩條路線：

⚙️ Workflows（預先編排工作流）

定義：由工程師寫好固定程式碼步驟，LLM 只在特定關卡負責分析、翻譯或檢查。

優點：路徑可預測、穩定度高、成本可控，適合 80% 以上的企業自動化任務。

🧭 Autonomous Agents（自主代理人）

定義：不寫死執行路線，讓 LLM 自己決定要呼叫幾次工具、何時停止。

優點：極具彈性，適合開放式研究或複雜除錯（如自動寫程式修 Bug），但需設步數上限防失控。

Wiki 條目：wiki/concepts/05-workflows-vs-autonomous-agents.md 引用：[[src-04]]
05. 常見 Workflow 設計模式

業界最實用的三種 Agentic Workflow 模式

在實際開發中，將不同功能的 LLM 節點串接起來，往往比單一巨大模型更可靠：

1. Prompt Chaining
（提示鏈流水線）

把任務拆成「大綱生成 $\rightarrow$ 檢查格式 Gate $\rightarrow$ 擴寫內文」，每一步都先驗收再往下走。

2. Routing
（智慧路由分流）

先用輕量模型判斷問題類型（退款 / 技術支援 / 閒聊），再派發給對應的專家模型處理。

3. Evaluator-Optimizer
（生成與審查迴圈）

一個 AI 負責產出草稿，另一個 AI 扮演嚴格審稿員挑毛病，退回修改直到達標為止！

✨ 彩蛋：我們這次製作「LLM Wiki $\rightarrow$ 教學 HTML 簡報」的作業流程，正是標準的 Prompt Chaining + Evaluator-Optimizer 混合架構！
